   48: =head1 NAME
   49: 
   50: Class::Shared - Keep one instance of a class and let other processes call it
   51: 
   52: =head1 SYNOPSIS
   53: 
   54: The usual way to use this distribution is through L<Class::Shared::Frontend>.
   55: Each example below is a different real-world pattern.
   56: 
   57:     # 1. The simplest case: share one class between many processes.
   58:     use Class::Shared::Frontend;
   59: 
   60:     my $simple = Class::Shared::Frontend->new('Class::Simple');
   61: 
   62:     $simple->foo('hello');          # runs in the shared backend
   63:     print $simple->foo(), "\n";     # prints "hello"
   64: 
   65:     # 2. Give the class its constructor arguments.  They are used once, when
   66:     #    the object is made, and must be plain data (no code references).
   67:     my $logger = Class::Shared::Frontend->new('My::Logger',
   68:         ctor => [ level => 'debug', file => '/var/log/app.log' ],
   69:     );
   70: 
   71:     my @all = $logger->lines();     # list context is kept
   72:     my $n   = $logger->lines();     # scalar context is kept too
   73: 
   74:     # 3. Use a backend on another machine, over TLS with client certificates.
   75:     my $remote = Class::Shared::Frontend->new('Class::Simple',
   76:         host       => 'classhost.example.com',
   77:         port       => 7000,
   78:         tls_ca     => 'ca.pem',
   79:         tls_cert   => 'client.pem',
   80:         tls_key    => 'client-key.pem',
   81:         token_file => '/etc/class-shared/token',
   82:     );
   83: 
   84:     # 4. Look after the backend yourself, from the shell.
   85:     #      class-shared start        # start it in the background
   86:     #      class-shared status       # ask what it is doing
   87:     #      class-shared stop         # ask it to stop
   88: 
   89:     # 5. Use the helper functions to write your own client.
   90:     use Class::Shared ();
   91: 
   92:     my $dir = Class::Shared::default_dir();
   93:     my ($ok, $why) = Class::Shared::ensure_dir($dir);
   94:     die "cannot use $dir: $why" unless $ok;
   95: 
   96:     my $socket = Class::Shared::socket_path($dir);

   98: =head1 DESCRIPTION
   99: 
  100: Perl has no equivalent of a shared library for classes: every process loads
  101: its own copy of F<Class/Simple.pm>, runs its own constructors and keeps its
  102: own state.  For a large class used by many short lived processes that is a lot
  103: of memory and a lot of start up time.
  104: 
  105: Class::Shared moves the code into one process and lets the others keep a small
  106: proxy: a L<Class::Shared::Frontend> standing in for one object, held by a
  107: L<Class::Shared::Backend> that loaded the class once and does the work.
  108: 
  109:     client process            singleton backend process
  110:     --------------            -------------------------
  111:     Frontend (object #1)  --socket-->  Class::Shared::Backend
  112:     Frontend (object #2)  --socket-->  |-- Class::Simple (code, loaded once)
  113:     Frontend (object #3)  --socket-->  |-- object #1
  114:                                        |-- object #2
  115:                                        `-- object #3
  116: 
  117: So there is one copy of the class in the system and as many objects as there are
  118: frontends: C<< Class::Shared::Frontend->new('Class::Simple', ...) >> is one call
  119: to C<< Class::Simple->new(...) >>, in the backend.
  120: 
  121: The arguments for that constructor go in C<ctor>, as an array reference:
  122: C<ctor =E<gt> [verbose =E<gt> 1]> is
  123: C<< Class::Simple->new(verbose =E<gt> 1) >>.  They are used once, when the
  124: frontend connects and asks the backend for the object, and they travel over the
  125: socket, so they must be plain data -- a code reference cannot be sent.  If the
  126: constructor dies, the frontend's C<new> dies too, naming the class and the error
  127: the backend reported.
  128: 
  129: L<Class::Shared::Frontend> lists every option this constructor takes.
  130: 
  131: The frontend never loads the target class, so it stays cheap.  An object lives
  132: as long as the connection that made it; when the frontend goes, the backend
  133: destroys the object, so its C<DESTROY> runs once, in the backend.
  134: 
  135: One backend serves every class its clients ask for.  A client names the class it
  136: wants in its first message, the handshake, and the backend loads that module
  137: then, once per class, however many clients ask for it.  The backend may be on
  138: this machine (a unix socket, see C<Class::Shared::default_dir>) or on another
  139: one (TCP).
  140: 
  141: Class::Shared is for Unix-like systems: unix sockets, POSIX directory
  142: permissions and C<fork> are what make a backend reachable, private and
  143: startable.  See L</PLATFORMS>.
  144: 
  145: This page documents the helper functions that the frontend, the backend and the
  146: command line program share.  Start with L<Class::Shared::Frontend> if you only
  147: want to use a shared class.

 1196: =head1 ENCODING
 1197: 
 1198: Class::Shared moves text between processes, so it matters which parts accept
 1199: more than plain English letters.
 1200: 
 1201: =over 4
 1202: 
 1203: =item Arguments, results and error text: full Unicode.
 1204: 
 1205: The arguments you pass to a method, the C<ctor> list, the values a method
 1206: returns and the text of an exception all travel through L<Storable>, which
 1207: keeps Perl strings exactly as they are.  Accented letters, Chinese, Japanese,
 1208: Arabic and emoji all arrive unchanged, with their "UTF-8 flag" kept.  This was
 1209: checked with a round trip of C<"caf\x{e9}">, C<"\x{1F600}"> and a Japanese word.
 1210: 
 1211: Bytes and characters are kept apart.  A byte string comes back as a byte string
 1212: and a character string as a character string.  So decode your input (for
 1213: example with L<Encode>) before you send it, and encode it when you print it.
 1214: 
 1215: =item Class names: ASCII only.
 1216: 
 1217: A class name may contain only the letters A to Z (either case), digits and
 1218: underscores, joined by C<::>.  A class with non-ASCII letters in its name is
 1219: refused by L</validate_class>, even though Perl itself would allow it.
 1220: 
 1221: =item Method names: ASCII is safe.
 1222: 
 1223: A method name is passed on as given.  Use ASCII names; a name that does not
 1224: exist is reported as "has no method".
 1225: 
 1226: =item Secrets (token, token file): ASCII only.
 1227: 
 1228: Use only ASCII characters in a token.  The token file is read as bytes, but a
 1229: C<token> you give in your program is a Perl string.  The word C<caf\x{e9}> has
 1230: different bytes in the two forms and so gives a different digest, and a
 1231: character above code point 255 stops the digest from being calculated at all.
 1232: Both sides would then fail to agree, and the connection is refused.
 1233: 
 1234: =item File and directory names: ASCII is safest.
 1235: 
 1236: Paths (C<dir>, C<socket>, C<log>, certificate files) are handed to the operating
 1237: system as they are.  Non-ASCII names work if every program uses the same bytes,
 1238: but they are not tested here.  The 100 character limit on a socket path counts
 1239: characters.  Perl gives a socket one byte for each character up to code point
 1240: 255, so an accepted path is not cut short.  A path with a higher character in a
 1241: character string cannot be used as a socket: connecting or binding dies with
 1242: C<Wide character>.  Encode such a name to bytes first; each byte then counts
 1243: towards the limit.
 1244: 
 1245: =item Fingerprints: hexadecimal digits only.
 1246: 
 1247: See L</normalise_fingerprint>.
 1248: 
 1249: =item The backend log: be careful.
 1250: 
 1251: The log file has no encoding layer.  Text that has only characters up to code
 1252: point 255 (such as C<caf\x{e9}>) is written as one byte per character, which is
 1253: not UTF-8.  Text with a higher character (such as an emoji) is written as UTF-8
 1254: and Perl prints a C<Wide character> warning.  A log that contains both is mixed.
 1255: Log lines are mostly the backend's own English messages; the main way for other
 1256: text to appear is an error from your own class.
 1257: 
 1258: =back

 1260: =head1 COMMON PITFALLS
 1261: 
 1262: =over 4
 1263: 
 1264: =item Class variables are shared by every client.
 1265: 
 1266: Each frontend has its own object, but all objects of a class live in one
 1267: process, so a package variable (C<our $COUNT>) or other class data is shared by
 1268: all clients.  A change made by one client is seen by all the others.  Keep state
 1269: in the object, not in the package.
 1270: 
 1271: =item The backend is one process: it does one thing at a time.
 1272: 
 1273: A slow method makes every other client wait, whatever class they use.
 1274: 
 1275: =item The backend's environment is not yours.
 1276: 
 1277: Setting C<$ENV{FOO}>, calling C<chdir>, or opening a file in your own process
 1278: changes nothing in the backend.  Pass what a method needs as arguments.
 1279: 
 1280: =item Only plain data can cross.
 1281: 
 1282: Strings, numbers, C<undef>, array references and hash references can be sent.
 1283: Code references, file handles and tied or inside-out objects cannot.  An
 1284: argument that cannot be sent makes the call fail.  In this version the failure
 1285: is reported as "lost the backend" and it also closes the connection, so the
 1286: object is gone.  Check your arguments before the call.
 1287: 
 1288: =item Context is kept, so list rules still apply.
 1289: 
 1290: A method that returns C<(1, 2, 3)> gives the last value, 3, in scalar context.
 1291: That is normal Perl, and it is the same through a frontend.
 1292: 
 1293: =item C<undef> is a value.
 1294: 
 1295: C<undef> is sent and returned faithfully.  A method that returns C<undef> in list
 1296: context gives a list of one element, not an empty list.
 1297: 
 1298: =item C<ensure_dir> returns a pair; the other functions die.
 1299: 
 1300: Test C<$ok>, the first value of the pair.  The pair as a whole is never an empty
 1301: list, so testing the list itself tells you nothing.
 1302: 
 1303: =item C<ensure_dir> makes only one directory.
 1304: 
 1305: If the parent does not exist, it fails with "No such file or directory".  Create
 1306: the parent first.
 1307: 
 1308: =item An over-long socket path is refused.
 1309: 
 1310: Keep C<dir> or C<socket> short (100 characters at most).
 1311: 
 1312: =item A token file's trailing white space is removed.
 1313: 
 1314: A secret whose last character is meant to be a space or a new line cannot be
 1315: stored in a token file.  Use ordinary printable characters.
 1316: 
 1317: =item A unix socket takes no token and no TLS.
 1318: 
 1319: Passing one is an error, on purpose, so that it never looks like extra
 1320: protection.
 1321: 
 1322: =back

 1324: =head1 TRANSPORT SECURITY
 1325: 
 1326: Authentication belongs to the transport, and the two transports are
 1327: deliberately different.
 1328: 
 1329: A unix socket is created mode 0600 in a directory only its owner can write to,
 1330: so the kernel has already decided who may connect: there is no token and no TLS,
 1331: and no frame carries a digest.  The backend, the frontend and L<class-shared>
 1332: refuse both for a unix socket rather than let either look like a defence.
 1333: 
 1334: TCP is the opposite case.  A port is reachable by anybody who can route to it,
 1335: and treating a frame means running what the sender put in it, so a TCP listener
 1336: is a TLS listener: it needs a certificate and its key to prove which backend it
 1337: is, and a CA to check client certificates against, and it will not start without
 1338: all three.  Clients must present a certificate that CA signed, and must verify
 1339: the backend's certificate against the CA that signed it -- name included -- or
 1340: against a pinned SHA-256 fingerprint of that one certificate, which stands in
 1341: for both the CA and the name.  A client whose certificate the backend cannot
 1342: verify is dropped during the handshake and never receives a frame.
 1343: 
 1344: TLS answers who is on the other end and makes the bytes unreadable.  The token is
 1345: kept on top of it, as a second and independent check: with a token every frame
 1346: in both directions carries an HMAC-SHA-256 of its body, and the digest is
 1347: verified before L<Storable::thaw> sees the body.  So a client that has a
 1348: certificate but not the shared secret still cannot make the backend
 1349: deserialise, and so run, bytes of its choosing.  The digest authenticates one
 1350: frame; TLS authenticates the connection and encrypts it.  Both, because either
 1351: one alone has been enough to lose a system.
 1352: 
 1353: See L<Class::Shared::Backend/SECURITY> for the backend's side of it and
 1354: L<Class::Shared::Protocol> for the framing.
 1355: 
 1356: =head2 Making the certificates
 1357: 
 1358: A TCP listener needs four files: a CA, the listener's certificate and key, and
 1359: a certificate for every client.  OpenSSL makes them in three steps.  The CA's
 1360: key signs certificates and is not needed on the machines that use them.
 1361: 
 1362:     # 1. A CA of your own.
 1363:     openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
 1364:         -keyout ca-key.pem -out ca.pem -subj '/CN=Class::Shared CA' \
 1365:         -addext 'basicConstraints=critical,CA:TRUE' \
 1366:         -addext 'keyUsage=critical,keyCertSign,cRLSign'
 1367: 
 1368: The listener's certificate has to name the address clients connect to, in
 1369: C<subjectAltName>: a C<DNS:> entry for a hostname, an C<IP:> entry for an
 1370: address, or both.
 1371: 
 1372:     # 2. The listener's certificate.  Put your own addresses in server.ext.
 1373:     printf 'subjectAltName = DNS:classhost.example.com, IP:127.0.0.1\n' > server.ext
 1374:     printf 'extendedKeyUsage = serverAuth\n' >> server.ext
 1375:     openssl req -new -newkey rsa:2048 -nodes -subj '/CN=classhost.example.com' \
 1376:         -keyout server-key.pem -out server.csr
 1377:     openssl x509 -req -in server.csr -CA ca.pem -CAkey ca-key.pem \
 1378:         -CAcreateserial -days 3650 -out server.pem -extfile server.ext
 1379: 
 1380: Each client needs a certificate of its own.  The backend cannot tell one from
 1381: another beyond this, so give each client, or each pair of them, their own.
 1382: 
 1383:     # 3. A client certificate.
 1384:     printf 'extendedKeyUsage = clientAuth\n' > client.ext
 1385:     openssl req -new -newkey rsa:2048 -nodes -subj '/CN=class-shared client' \
 1386:         -keyout client-key.pem -out client.csr
 1387:     openssl x509 -req -in client.csr -CA ca.pem -CAkey ca-key.pem \
 1388:         -CAcreateserial -days 3650 -out client.pem -extfile client.ext
 1389: 
 1390: The listener is given three of the files:
 1391: 
 1392:     class-shared start --listen tcp:0.0.0.0:7000 \
 1393:         --token-file /etc/class-shared/token \
 1394:         --tls-cert server.pem --tls-key server-key.pem --tls-ca ca.pem
 1395: 
 1396: and every client the other three:
 1397: 
 1398:     my $simple = Class::Shared::Frontend->new('Class::Simple',
 1399:         host       => 'classhost.example.com',
 1400:         port       => 7000,
 1401:         tls_ca     => 'ca.pem',
 1402:         tls_cert   => 'client.pem',
 1403:         tls_key    => 'client-key.pem',
 1404:         token_file => '/etc/class-shared/token',
 1405:     );
 1406: 
 1407: A frontend that pins the listener's certificate instead of trusting the CA skips
 1408: C<tls_ca> and passes C<tls_fingerprint> the digest that
 1409: C<openssl x509 -in server.pem -noout -fingerprint -sha256> prints.  That works
 1410: with a self-signed certificate too, and then the CA is only needed for the
 1411: clients.  F<t/certs/make-certs.sh> in the distribution generates this set, plus
 1412: a second CA and impostor certificates, for the tests.

 1414: =head1 LIMITATIONS
 1415: 
 1416: =over 4
 1417: 
 1418: =item *
 1419: 
 1420: A unix socket is not encrypted: file permissions decide who may connect, and
 1421: anything that can read the socket can read the traffic on it.  TCP is always
 1422: TLS, and has no unencrypted mode.
 1423: 
 1424: =item *
 1425: 
 1426: One backend per directory answers one call at a time, so a slow method delays
 1427: every client of that backend, whatever class they are using.
 1428: 
 1429: =item *
 1430: 
 1431: Each frontend is one connection: many objects in one process means many file
 1432: descriptors in both processes.
 1433: 
 1434: =item *
 1435: 
 1436: Arguments and return values travel through L<Storable>; filehandles, code
 1437: references and tied or inside-out objects do not.
 1438: 
 1439: =item *
 1440: 
 1441: An object cannot outlive its connection, so it cannot be handed to another
 1442: process; it lives exactly as long as the frontend that made it.
 1443: 
 1444: =item *
 1445: 
 1446: The backend is a separate process, so nothing about your process reaches it
 1447: unless you send it.  Setting C<$ENV{FOO}> in a frontend does not set it in the
 1448: backend, and a method that reads C<%ENV> (or C<chdir>, or a global, or a file
 1449: handle) sees the backend's environment, not yours: its C<%ENV> is the one the
 1450: backend was started with, and every client shares those values.  Pass such
 1451: state as arguments if it matters, or set the environment when you start the
 1452: backend.
 1453: 
 1454: =item *
 1455: 
 1456: A client may call a method only by its plain name.  A package-qualified name
 1457: such as C<Other::Package::function> is refused, and so are C<new>, C<DESTROY>
 1458: and C<AUTOLOAD>.  This is not a sandbox: a client that has passed the
 1459: transport's authentication can already make the backend load any module and
 1460: call the methods of what it constructs, so the backend is only as safe as the
 1461: clients allowed to reach it.
 1462: 
 1463: =back

 1465: =head1 PLATFORMS
 1466: 
 1467: Unix-like systems only.  A backend needs three things this distribution cannot
 1468: do without:
 1469: 
 1470: =over 4
 1471: 
 1472: =item *
 1473: 
 1474: unix domain sockets, which is how a frontend reaches a backend on this machine
 1475: and starts one when there is none;
 1476: 
 1477: =item *
 1478: 
 1479: POSIX directory permissions, which are the whole of a unix socket's
 1480: authentication: the socket is mode 0600 inside a directory only its owner can
 1481: write to, so the kernel decides who may connect;
 1482: 
 1483: =item *
 1484: 
 1485: a real C<fork>, which is how a frontend starts a backend in the background.
 1486: 
 1487: =back
 1488: 
 1489: A perl without unix domain sockets can run none of it, so that is the question
 1490: the check asks, rather than a list of operating systems: a Cygwin perl has the
 1491: sockets and works.  Windows has had the sockets since Windows 10, but an
 1492: MSWin32 perl still cannot run a backend: its C<stat> reports the same mode bits
 1493: for every directory, so none there can be shown to be owner-only and
 1494: C<Class::Shared::ensure_dir> refuses them all.
 1495: 
 1496: The refusal names what is missing: C<Class::Shared::ensure_dir> and
 1497: C<Class::Shared::socket_path> die with that explanation on a perl without the
 1498: sockets, and C<Class::Shared::ensure_dir> refuses the directories it cannot
 1499: show to be owner-only.
 1500: 
 1501: It installs there anyway, and F<Makefile.PL> says so as it runs.  Refusing to
 1502: install would take away L<Class::Shared::Protocol>, which is pure Perl and can
 1503: talk to a backend from a machine that cannot run one, and would leave such a
 1504: platform with nothing to report but a failed install.
 1505: 
 1506: The wire protocol, L<Class::Shared::Protocol>, is pure Perl and loads on any
 1507: platform, so it can be used to talk to a backend from a machine that cannot run
 1508: one.

 1709: =head1 STATE DIAGRAM
 1710: 
 1711: The functions in this file keep almost no state.  The one piece they do keep is
 1712: the answer to "can this perl make a unix socket?", which is worked out once,
 1713: the first time it is needed, and then never changes.
 1714: 
 1715:                   both tries work
 1716:     +---------+ -------------------------> +---------+ <---+
 1717:     | UNKNOWN |                            | UNIX_OK |     | every later call
 1718:     +---------+ ---+                       +---------+ ----+ (no change)
 1719:                    |  try fails
 1720:                    |                       +---------+ <---+
 1721:                    +---------------------> | NO_UNIX |     | every later call
 1722:                                            +---------+ ----+ (calls die)
 1723: 
 1724: A directory, as seen by L</ensure_dir>, moves through these states.  The
 1725: function does not remember them; they describe what it finds and what it does.
 1726: 
 1727:     +---------+   mkdir 0700 works    +---------+
 1728:     | MISSING | --------------------> | PRESENT |   (it existed, or was just made)
 1729:     +---------+                       +---------+
 1730:          |                              |      |
 1731:          | mkdir fails                  |      | I own it, and group and
 1732:          | (parent missing, no          |      | other cannot write to it
 1733:          |  permission, ...)            |      v
 1734:          |                              |   +------+
 1735:          |                              |   | SAFE |   returns (1, undef)
 1736:          |                              |   +------+
 1737:          |                              | someone else owns it, or
 1738:          |                              | group or other can write to it
 1739:          v                              v
 1740:       +------------------------------------+
 1741:       | REFUSED   returns (0, $why)        |
 1742:       +------------------------------------+
 1743: 
 1744: =over 4
 1745: 
 1746: =item UNKNOWN to UNIX_OK or NO_UNIX
 1747: 
 1748: Trigger: the first call to C<socket_path> or C<ensure_dir> (or the check in
 1749: F<Makefile.PL>).  Action: try to name a unix socket (C<pack_sockaddr_un>) and to
 1750: make a pair of connected ones (C<socketpair>).  The
 1751: answer is stored in C<$Class::Shared::UNIX_SOCKETS> and is never asked again.
 1752: 
 1753: =item UNIX_OK, no change
 1754: 
 1755: Trigger: any later call.  Action: none; C<socket_path> and C<ensure_dir> work as
 1756: described above.
 1757: 
 1758: =item NO_UNIX, no change
 1759: 
 1760: Trigger: any later call to C<socket_path> or C<ensure_dir>.  Action: the call
 1761: dies with a message saying that this perl has no unix sockets.
 1762: 
 1763: =item MISSING to PRESENT
 1764: 
 1765: Trigger: C<ensure_dir> on a directory that does not exist but whose parent does.
 1766: Action: C<mkdir> with mode 0700.
 1767: 
 1768: =item MISSING to REFUSED
 1769: 
 1770: Trigger: the C<mkdir> fails, for example because the parent does not exist.
 1771: Action: return C<(0, $reason)>.
 1772: 
 1773: =item PRESENT to SAFE
 1774: 
 1775: Trigger: C<ensure_dir> finds that this user owns the directory and that group
 1776: and other users cannot write to it.  Action: return C<(1, undef)>.
 1777: 
 1778: =item PRESENT to REFUSED
 1779: 
 1780: Trigger: C<ensure_dir> finds a different owner, or that group or other users can
 1781: write to it.  Action: return C<(0, $reason)>.
 1782: 
 1783: =back
