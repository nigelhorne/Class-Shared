   48: =head1 NAME
   49: 
   50: Class::Shared - Keep one instance of a class and let other processes call it
   51: 
   52: =head1 SYNOPSIS
   53: 
   54: The usual way to use this distribution is through L<Class::Shared::Frontend>.
   55: Each example below is a different real-world pattern.
   56: 
   57:     # 1. The simplest case: share one class between many processes.
   58:     use Class::Shared::Frontend;
   59: 
   60:     my $simple = Class::Shared::Frontend->new('Class::Simple');
   61: 
   62:     $simple->foo('hello');          # runs in the shared backend
   63:     print $simple->foo(), "\n";     # prints "hello"
   64: 
   65:     # 2. Give the class its constructor arguments.  They are used once, when
   66:     #    the object is made, and must be plain data (no code references).
   67:     my $logger = Class::Shared::Frontend->new('My::Logger',
   68:         ctor => [ level => 'debug', file => '/var/log/app.log' ],
   69:     );
   70: 
   71:     my @all = $logger->lines();     # list context is kept
   72:     my $n   = $logger->lines();     # scalar context is kept too
   73: 
   74:     # 3. Use a backend on another machine, over TLS with client certificates.
   75:     my $remote = Class::Shared::Frontend->new('Class::Simple',
   76:         host       => 'classhost.example.com',
   77:         port       => 7000,
   78:         tls_ca     => 'ca.pem',
   79:         tls_cert   => 'client.pem',
   80:         tls_key    => 'client-key.pem',
   81:         token_file => '/etc/class-shared/token',
   82:     );
   83: 
   84:     # 4. Look after the backend yourself, from the shell.
   85:     #      class-shared start        # start it in the background
   86:     #      class-shared status       # ask what it is doing
   87:     #      class-shared stop         # ask it to stop
   88: 
   89:     # 5. Use the helper functions to write your own client.
   90:     use Class::Shared ();
   91: 
   92:     my $dir = Class::Shared::default_dir();
   93:     my ($ok, $why) = Class::Shared::ensure_dir($dir);
   94:     die "cannot use $dir: $why" unless $ok;
   95: 
   96:     my $socket = Class::Shared::socket_path($dir);

   98: =head1 DESCRIPTION
   99: 
  100: Perl has no equivalent of a shared library for classes: every process loads
  101: its own copy of F<Class/Simple.pm>, runs its own constructors and keeps its
  102: own state.  For a large class used by many short lived processes that is a lot
  103: of memory and a lot of start up time.
  104: 
  105: Class::Shared moves the code into one process and lets the others keep a small
  106: proxy: a L<Class::Shared::Frontend> standing in for one object, held by a
  107: L<Class::Shared::Backend> that loaded the class once and does the work.
  108: 
  109:     client process            singleton backend process
  110:     --------------            -------------------------
  111:     Frontend (object #1)  --socket-->  Class::Shared::Backend
  112:     Frontend (object #2)  --socket-->  |-- Class::Simple (code, loaded once)
  113:     Frontend (object #3)  --socket-->  |-- object #1
  114:                                        |-- object #2
  115:                                        `-- object #3
  116: 
  117: So there is one copy of the class in the system and as many objects as there are
  118: frontends: C<< Class::Shared::Frontend->new('Class::Simple', ...) >> is one call
  119: to C<< Class::Simple->new(...) >>, in the backend.
  120: 
  121: The arguments for that constructor go in C<ctor>, as an array reference:
  122: C<ctor =E<gt> [verbose =E<gt> 1]> is
  123: C<< Class::Simple->new(verbose =E<gt> 1) >>.  They are used once, when the
  124: frontend connects and asks the backend for the object, and they travel over the
  125: socket, so they must be plain data -- a code reference cannot be sent.  If the
  126: constructor dies, the frontend's C<new> dies too, naming the class and the error
  127: the backend reported.
  128: 
  129: L<Class::Shared::Frontend> lists every option this constructor takes.
  130: 
  131: The frontend never loads the target class, so it stays cheap.  An object lives
  132: as long as the connection that made it; when the frontend goes, the backend
  133: destroys the object, so its C<DESTROY> runs once, in the backend.
  134: 
  135: One backend serves every class its clients ask for.  A client names the class it
  136: wants in its first message, the handshake, and the backend loads that module
  137: then, once per class, however many clients ask for it.  The backend may be on
  138: this machine (a unix socket, see C<Class::Shared::default_dir>) or on another
  139: one (TCP).
  140: 
  141: Class::Shared is for Unix-like systems: unix sockets, POSIX directory
  142: permissions and C<fork> are what make a backend reachable, private and
  143: startable.  See L</PLATFORMS>.
  144: 
  145: This page documents the helper functions that the frontend, the backend and the
  146: command line program share.  Start with L<Class::Shared::Frontend> if you only
  147: want to use a shared class.

 1192: =head1 ENCODING
 1193: 
 1194: Class::Shared moves text between processes, so it matters which parts accept
 1195: more than plain English letters.
 1196: 
 1197: =over 4
 1198: 
 1199: =item Arguments, results and error text: full Unicode.
 1200: 
 1201: The arguments you pass to a method, the C<ctor> list, the values a method
 1202: returns and the text of an exception all travel through L<Storable>, which
 1203: keeps Perl strings exactly as they are.  Accented letters, Chinese, Japanese,
 1204: Arabic and emoji all arrive unchanged, with their "UTF-8 flag" kept.  This was
 1205: checked with a round trip of C<"caf\x{e9}">, C<"\x{1F600}"> and a Japanese word.
 1206: 
 1207: Bytes and characters are kept apart.  A byte string comes back as a byte string
 1208: and a character string as a character string.  So decode your input (for
 1209: example with L<Encode>) before you send it, and encode it when you print it.
 1210: 
 1211: =item Class names: ASCII only.
 1212: 
 1213: A class name may contain only the letters A to Z (either case), digits and
 1214: underscores, joined by C<::>.  A class with non-ASCII letters in its name is
 1215: refused by L</validate_class>, even though Perl itself would allow it.
 1216: 
 1217: =item Method names: ASCII is safe.
 1218: 
 1219: A method name is passed on as given.  Use ASCII names; a name that does not
 1220: exist is reported as "has no method".
 1221: 
 1222: =item Secrets (token, token file): ASCII only.
 1223: 
 1224: Use only ASCII characters in a token.  The token file is read as bytes, but a
 1225: C<token> you give in your program is a Perl string.  The word C<caf\x{e9}> has
 1226: different bytes in the two forms and so gives a different digest, and a
 1227: character above code point 255 stops the digest from being calculated at all.
 1228: Both sides would then fail to agree, and the connection is refused.
 1229: 
 1230: =item File and directory names: ASCII is safest.
 1231: 
 1232: Paths (C<dir>, C<socket>, C<log>, certificate files) are handed to the operating
 1233: system as they are.  Non-ASCII names work if every program uses the same bytes,
 1234: but they are not tested here.  The 100 character limit on a socket path counts
 1235: characters.  Perl gives a socket one byte for each character up to code point
 1236: 255, so an accepted path is not cut short.  A path with a higher character in a
 1237: character string cannot be used as a socket: connecting or binding dies with
 1238: C<Wide character>.  Encode such a name to bytes first; each byte then counts
 1239: towards the limit.
 1240: 
 1241: =item Fingerprints: hexadecimal digits only.
 1242: 
 1243: See L</normalise_fingerprint>.
 1244: 
 1245: =item The backend log: be careful.
 1246: 
 1247: The log file has no encoding layer.  Text that has only characters up to code
 1248: point 255 (such as C<caf\x{e9}>) is written as one byte per character, which is
 1249: not UTF-8.  Text with a higher character (such as an emoji) is written as UTF-8
 1250: and Perl prints a C<Wide character> warning.  A log that contains both is mixed.
 1251: Log lines are mostly the backend's own English messages; the main way for other
 1252: text to appear is an error from your own class.
 1253: 
 1254: =back

 1256: =head1 COMMON PITFALLS
 1257: 
 1258: =over 4
 1259: 
 1260: =item Class variables are shared by every client.
 1261: 
 1262: Each frontend has its own object, but all objects of a class live in one
 1263: process, so a package variable (C<our $COUNT>) or other class data is shared by
 1264: all clients.  A change made by one client is seen by all the others.  Keep state
 1265: in the object, not in the package.
 1266: 
 1267: =item The backend is one process: it does one thing at a time.
 1268: 
 1269: A slow method makes every other client wait, whatever class they use.
 1270: 
 1271: =item The backend's environment is not yours.
 1272: 
 1273: Setting C<$ENV{FOO}>, calling C<chdir>, or opening a file in your own process
 1274: changes nothing in the backend.  Pass what a method needs as arguments.
 1275: 
 1276: =item Only plain data can cross.
 1277: 
 1278: Strings, numbers, C<undef>, array references and hash references can be sent.
 1279: Code references, file handles and tied or inside-out objects cannot.  An
 1280: argument that cannot be sent makes the call fail.  In this version the failure
 1281: is reported as "lost the backend" and it also closes the connection, so the
 1282: object is gone.  Check your arguments before the call.
 1283: 
 1284: =item Context is kept, so list rules still apply.
 1285: 
 1286: A method that returns C<(1, 2, 3)> gives the last value, 3, in scalar context.
 1287: That is normal Perl, and it is the same through a frontend.
 1288: 
 1289: =item C<undef> is a value.
 1290: 
 1291: C<undef> is sent and returned faithfully.  A method that returns C<undef> in list
 1292: context gives a list of one element, not an empty list.
 1293: 
 1294: =item C<ensure_dir> returns a pair; the other functions die.
 1295: 
 1296: Test C<$ok>, the first value of the pair.  The pair as a whole is never an empty
 1297: list, so testing the list itself tells you nothing.
 1298: 
 1299: =item C<ensure_dir> makes only one directory.
 1300: 
 1301: If the parent does not exist, it fails with "No such file or directory".  Create
 1302: the parent first.
 1303: 
 1304: =item An over-long socket path is refused.
 1305: 
 1306: Keep C<dir> or C<socket> short (100 characters at most).
 1307: 
 1308: =item A token file's trailing white space is removed.
 1309: 
 1310: A secret whose last character is meant to be a space or a new line cannot be
 1311: stored in a token file.  Use ordinary printable characters.
 1312: 
 1313: =item A unix socket takes no token and no TLS.
 1314: 
 1315: Passing one is an error, on purpose, so that it never looks like extra
 1316: protection.
 1317: 
 1318: =back

 1320: =head1 TRANSPORT SECURITY
 1321: 
 1322: Authentication belongs to the transport, and the two transports are
 1323: deliberately different.
 1324: 
 1325: A unix socket is created mode 0600 in a directory only its owner can write to,
 1326: so the kernel has already decided who may connect: there is no token and no TLS,
 1327: and no frame carries a digest.  The backend, the frontend and L<class-shared>
 1328: refuse both for a unix socket rather than let either look like a defence.
 1329: 
 1330: TCP is the opposite case.  A port is reachable by anybody who can route to it,
 1331: and treating a frame means running what the sender put in it, so a TCP listener
 1332: is a TLS listener: it needs a certificate and its key to prove which backend it
 1333: is, and a CA to check client certificates against, and it will not start without
 1334: all three.  Clients must present a certificate that CA signed, and must verify
 1335: the backend's certificate against the CA that signed it -- name included -- or
 1336: against a pinned SHA-256 fingerprint of that one certificate, which stands in
 1337: for both the CA and the name.  A client whose certificate the backend cannot
 1338: verify is dropped during the handshake and never receives a frame.
 1339: 
 1340: TLS answers who is on the other end and makes the bytes unreadable.  The token is
 1341: kept on top of it, as a second and independent check: with a token every frame
 1342: in both directions carries an HMAC-SHA-256 of its body, and the digest is
 1343: verified before L<Storable::thaw> sees the body.  So a client that has a
 1344: certificate but not the shared secret still cannot make the backend
 1345: deserialise, and so run, bytes of its choosing.  The digest authenticates one
 1346: frame; TLS authenticates the connection and encrypts it.  Both, because either
 1347: one alone has been enough to lose a system.
 1348: 
 1349: See L<Class::Shared::Backend/SECURITY> for the backend's side of it and
 1350: L<Class::Shared::Protocol> for the framing.
 1351: 
 1352: =head2 Making the certificates
 1353: 
 1354: A TCP listener needs four files: a CA, the listener's certificate and key, and
 1355: a certificate for every client.  OpenSSL makes them in three steps.  The CA's
 1356: key signs certificates and is not needed on the machines that use them.
 1357: 
 1358:     # 1. A CA of your own.
 1359:     openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
 1360:         -keyout ca-key.pem -out ca.pem -subj '/CN=Class::Shared CA' \
 1361:         -addext 'basicConstraints=critical,CA:TRUE' \
 1362:         -addext 'keyUsage=critical,keyCertSign,cRLSign'
 1363: 
 1364: The listener's certificate has to name the address clients connect to, in
 1365: C<subjectAltName>: a C<DNS:> entry for a hostname, an C<IP:> entry for an
 1366: address, or both.
 1367: 
 1368:     # 2. The listener's certificate.  Put your own addresses in server.ext.
 1369:     printf 'subjectAltName = DNS:classhost.example.com, IP:127.0.0.1\n' > server.ext
 1370:     printf 'extendedKeyUsage = serverAuth\n' >> server.ext
 1371:     openssl req -new -newkey rsa:2048 -nodes -subj '/CN=classhost.example.com' \
 1372:         -keyout server-key.pem -out server.csr
 1373:     openssl x509 -req -in server.csr -CA ca.pem -CAkey ca-key.pem \
 1374:         -CAcreateserial -days 3650 -out server.pem -extfile server.ext
 1375: 
 1376: Each client needs a certificate of its own.  The backend cannot tell one from
 1377: another beyond this, so give each client, or each pair of them, their own.
 1378: 
 1379:     # 3. A client certificate.
 1380:     printf 'extendedKeyUsage = clientAuth\n' > client.ext
 1381:     openssl req -new -newkey rsa:2048 -nodes -subj '/CN=class-shared client' \
 1382:         -keyout client-key.pem -out client.csr
 1383:     openssl x509 -req -in client.csr -CA ca.pem -CAkey ca-key.pem \
 1384:         -CAcreateserial -days 3650 -out client.pem -extfile client.ext
 1385: 
 1386: The listener is given three of the files:
 1387: 
 1388:     class-shared start --listen tcp:0.0.0.0:7000 \
 1389:         --token-file /etc/class-shared/token \
 1390:         --tls-cert server.pem --tls-key server-key.pem --tls-ca ca.pem
 1391: 
 1392: and every client the other three:
 1393: 
 1394:     my $simple = Class::Shared::Frontend->new('Class::Simple',
 1395:         host       => 'classhost.example.com',
 1396:         port       => 7000,
 1397:         tls_ca     => 'ca.pem',
 1398:         tls_cert   => 'client.pem',
 1399:         tls_key    => 'client-key.pem',
 1400:         token_file => '/etc/class-shared/token',
 1401:     );
 1402: 
 1403: A frontend that pins the listener's certificate instead of trusting the CA skips
 1404: C<tls_ca> and passes C<tls_fingerprint> the digest that
 1405: C<openssl x509 -in server.pem -noout -fingerprint -sha256> prints.  That works
 1406: with a self-signed certificate too, and then the CA is only needed for the
 1407: clients.  F<t/certs/make-certs.sh> in the distribution generates this set, plus
 1408: a second CA and impostor certificates, for the tests.

 1410: =head1 LIMITATIONS
 1411: 
 1412: =over 4
 1413: 
 1414: =item *
 1415: 
 1416: A unix socket is not encrypted: file permissions decide who may connect, and
 1417: anything that can read the socket can read the traffic on it.  TCP is always
 1418: TLS, and has no unencrypted mode.
 1419: 
 1420: =item *
 1421: 
 1422: One backend per directory answers one call at a time, so a slow method delays
 1423: every client of that backend, whatever class they are using.
 1424: 
 1425: =item *
 1426: 
 1427: Each frontend is one connection: many objects in one process means many file
 1428: descriptors in both processes.
 1429: 
 1430: =item *
 1431: 
 1432: Arguments and return values travel through L<Storable>; filehandles, code
 1433: references and tied or inside-out objects do not.
 1434: 
 1435: =item *
 1436: 
 1437: An object cannot outlive its connection, so it cannot be handed to another
 1438: process; it lives exactly as long as the frontend that made it.
 1439: 
 1440: =item *
 1441: 
 1442: The backend is a separate process, so nothing about your process reaches it
 1443: unless you send it.  Setting C<$ENV{FOO}> in a frontend does not set it in the
 1444: backend, and a method that reads C<%ENV> (or C<chdir>, or a global, or a file
 1445: handle) sees the backend's environment, not yours: its C<%ENV> is the one the
 1446: backend was started with, and every client shares those values.  Pass such
 1447: state as arguments if it matters, or set the environment when you start the
 1448: backend.
 1449: 
 1450: =item *
 1451: 
 1452: A client may call a method only by its plain name.  A package-qualified name
 1453: such as C<Other::Package::function> is refused, and so are C<new>, C<DESTROY>
 1454: and C<AUTOLOAD>.  This is not a sandbox: a client that has passed the
 1455: transport's authentication can already make the backend load any module and
 1456: call the methods of what it constructs, so the backend is only as safe as the
 1457: clients allowed to reach it.
 1458: 
 1459: =back

 1461: =head1 PLATFORMS
 1462: 
 1463: Unix-like systems only.  A backend needs three things this distribution cannot
 1464: do without:
 1465: 
 1466: =over 4
 1467: 
 1468: =item *
 1469: 
 1470: unix domain sockets, which is how a frontend reaches a backend on this machine
 1471: and starts one when there is none;
 1472: 
 1473: =item *
 1474: 
 1475: POSIX directory permissions, which are the whole of a unix socket's
 1476: authentication: the socket is mode 0600 inside a directory only its owner can
 1477: write to, so the kernel decides who may connect;
 1478: 
 1479: =item *
 1480: 
 1481: a real C<fork>, which is how a frontend starts a backend in the background.
 1482: 
 1483: =back
 1484: 
 1485: A perl without unix domain sockets can run none of it, so that is the question
 1486: the check asks, rather than a list of operating systems: a Cygwin perl has the
 1487: sockets and works.  Windows has had the sockets since Windows 10, but an
 1488: MSWin32 perl still cannot run a backend: its C<stat> reports the same mode bits
 1489: for every directory, so none there can be shown to be owner-only and
 1490: C<Class::Shared::ensure_dir> refuses them all.
 1491: 
 1492: The refusal names what is missing: C<Class::Shared::ensure_dir> and
 1493: C<Class::Shared::socket_path> die with that explanation on a perl without the
 1494: sockets, and C<Class::Shared::ensure_dir> refuses the directories it cannot
 1495: show to be owner-only.
 1496: 
 1497: It installs there anyway, and F<Makefile.PL> says so as it runs.  Refusing to
 1498: install would take away L<Class::Shared::Protocol>, which is pure Perl and can
 1499: talk to a backend from a machine that cannot run one, and would leave such a
 1500: platform with nothing to report but a failed install.
 1501: 
 1502: The wire protocol, L<Class::Shared::Protocol>, is pure Perl and loads on any
 1503: platform, so it can be used to talk to a backend from a machine that cannot run
 1504: one.

 1698: =head1 STATE DIAGRAM
 1699: 
 1700: The functions in this file keep almost no state.  The one piece they do keep is
 1701: the answer to "can this perl make a unix socket?", which is worked out once,
 1702: the first time it is needed, and then never changes.
 1703: 
 1704:                 try socketpair() works
 1705:     +---------+ -------------------------> +---------+ <---+
 1706:     | UNKNOWN |                            | UNIX_OK |     | every later call
 1707:     +---------+ ---+                       +---------+ ----+ (no change)
 1708:                    |  try fails
 1709:                    |                       +---------+ <---+
 1710:                    +---------------------> | NO_UNIX |     | every later call
 1711:                                            +---------+ ----+ (calls die)
 1712: 
 1713: A directory, as seen by L</ensure_dir>, moves through these states.  The
 1714: function does not remember them; they describe what it finds and what it does.
 1715: 
 1716:     +---------+   mkdir 0700 works    +---------+
 1717:     | MISSING | --------------------> | PRESENT |   (it existed, or was just made)
 1718:     +---------+                       +---------+
 1719:          |                              |      |
 1720:          | mkdir fails                  |      | I own it, and group and
 1721:          | (parent missing, no          |      | other cannot write to it
 1722:          |  permission, ...)            |      v
 1723:          |                              |   +------+
 1724:          |                              |   | SAFE |   returns (1, undef)
 1725:          |                              |   +------+
 1726:          |                              | someone else owns it, or
 1727:          |                              | group or other can write to it
 1728:          v                              v
 1729:       +------------------------------------+
 1730:       | REFUSED   returns (0, $why)        |
 1731:       +------------------------------------+
 1732: 
 1733: =over 4
 1734: 
 1735: =item UNKNOWN to UNIX_OK or NO_UNIX
 1736: 
 1737: Trigger: the first call to C<socket_path> or C<ensure_dir> (or the check in
 1738: F<Makefile.PL>).  Action: try to make a pair of connected unix sockets.  The
 1739: answer is stored in C<$Class::Shared::UNIX_SOCKETS> and is never asked again.
 1740: 
 1741: =item UNIX_OK, no change
 1742: 
 1743: Trigger: any later call.  Action: none; C<socket_path> and C<ensure_dir> work as
 1744: described above.
 1745: 
 1746: =item NO_UNIX, no change
 1747: 
 1748: Trigger: any later call to C<socket_path> or C<ensure_dir>.  Action: the call
 1749: dies with a message saying that this perl has no unix sockets.
 1750: 
 1751: =item MISSING to PRESENT
 1752: 
 1753: Trigger: C<ensure_dir> on a directory that does not exist but whose parent does.
 1754: Action: C<mkdir> with mode 0700.
 1755: 
 1756: =item MISSING to REFUSED
 1757: 
 1758: Trigger: the C<mkdir> fails, for example because the parent does not exist.
 1759: Action: return C<(0, $reason)>.
 1760: 
 1761: =item PRESENT to SAFE
 1762: 
 1763: Trigger: C<ensure_dir> finds that this user owns the directory and that group
 1764: and other users cannot write to it.  Action: return C<(1, undef)>.
 1765: 
 1766: =item PRESENT to REFUSED
 1767: 
 1768: Trigger: C<ensure_dir> finds a different owner, or that group or other users can
 1769: write to it.  Action: return C<(0, $reason)>.
 1770: 
 1771: =back
